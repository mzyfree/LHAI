# 裸K LLM 实盘辅助服务设计

## 1. 目标与边界

本服务将已经完成历史回测的裸K LLM 单股策略落地为本地实盘辅助系统。系统负责行情准备、候选筛选、LLM决策、硬风控、通知、人工成交回填、持仓与收益计算，不自动向券商下单。

第一版只实现：

- 今日决策
- 人工成交回填
- 当前持仓
- 账户与历史
- 系统状态与日志

交易复盘和策略研究页面暂不实现。回测成绩不显示在实盘首页，避免与真实账户收益混淆。

## 2. 冻结交易口径

实盘实现必须保持当前历史回测口径：

- 09:25只计算一次开盘广度。
- 开盘广度低于37%时，当天禁止新开仓。
- 开盘广度达到37%时，当天允许寻找买点，不增加盘中动态广度过滤。
- LLM可以输出市场描述，但不存在可执行的“谨慎”状态；最终开仓权限只有允许和禁止。
- 09:25固定生成最多3只观察股，盘中不重新扫描全A。
- 从09:35开始，每5分钟使用截至当前的5分钟K线判断。
- 任意时刻最多持有一只股票，使用可用资金买入，不加仓。
- 买入信号在下一根5分钟K线附近执行，实际成交以人工回填为准。
- A股T+1：买入当日不可卖出。
- T+1以后每5分钟判断持有或卖出，不设固定T+2退出。
- 卖出后允许买入当日固定Top3中的其他股票，但禁止当天买回刚卖出的股票。
- 不启用“前两个交易日连续涨停，第三日禁止买入”实验规则。
- 不增加“实际成交涨幅超过5%禁买”等尚未冻结的新规则。

硬风控继续由代码执行，LLM不能覆盖，包括涨停不可成交、上影线过滤、证据数量、结构与量能同时走弱时禁买等当前冻结条件。

## 3. 交易状态机

后台以数据库状态为准，模型建议本身不能改变持仓。

```text
盘前准备
  -> 09:25开仓权限与固定Top3
  -> 空仓等待盘中信号
  -> 买入建议待人工处理
  -> 人工回填买入
  -> T+0锁定持仓
  -> 下一交易日进入T+1可卖
  -> 持有或卖出建议
  -> 人工回填卖出
  -> 空仓，继续检查固定Top3
```

具体状态：

| 状态 | 系统行为 |
|---|---|
| `PREMARKET` | 准备前日数据、交易日和股票基础信息 |
| `ENTRY_BLOCKED` | 09:25广度低于37%，当天不再分析买点 |
| `WATCHING` | 空仓且有固定Top3，每5分钟判断买点 |
| `BUY_PENDING` | 已发出买入建议，等待人工执行或忽略 |
| `T0_LOCKED` | 已买入但当日不可卖，只保存行情和风险状态，不调用无效卖出决策 |
| `T1_MONITORING` | 持仓可卖，每5分钟判断卖点 |
| `SELL_PENDING` | 已发出卖出建议，等待人工执行或忽略 |
| `CLOSED` | 当日结束，更新收盘净值和统计 |

人工回填成功后才推进状态。建议未执行时，用户可以点击“忽略本次建议”恢复对应的观察或持仓监控状态。

## 4. 每日调度

建议调度如下：

| 时间 | 任务 |
|---|---|
| 09:25前 | 更新前日数据、特征、交易日和基础候选数据 |
| 09:25 | 获取集合竞价结果，计算开盘广度、热点板块和固定Top3 |
| 09:35起 | 交易时段内每5分钟执行一次有效状态判断 |
| 11:30-13:00 | 午间暂停 |
| 15:00 | 更新收盘行情、持仓市值、当日盈亏和运行摘要 |

最后允许新开仓的时间和最后卖出判断时间作为配置项保留。第一版建议分别为14:50和14:55。

以下状态不产生无意义的LLM调用：

- 当日禁止开仓且当前空仓
- `BUY_PENDING`或`SELL_PENDING`
- `T0_LOCKED`
- 非交易时段

## 5. 页面信息架构

### 5.1 今日决策

页面上半部分展示09:25结果：

- 交易日期和当前市场阶段
- 09:25开盘广度、37%门槛
- 今日开仓权限：允许或禁止
- 热点板块Top5
- 全天固定Top3观察股
- 数据截止时间和完整性
- LLM市场说明与风险，仅作解释

页面下半部分为盘中滚动决策盘：

- 最新决策时间
- 当前动作：等待、买入、T+0锁定、持有、卖出、停止交易
- 股票名称、代码、最新价和建议参考价
- 证据数量、置信度、理由和风险
- 硬规则拦截结果
- 下一次判断时间
- 当日历史决策列表

滚动盘同时承担决策时间轴功能，不再建设重复页面。

### 5.2 人工成交回填

用户只输入：

- 买入或卖出
- 股票代码
- 成交价格
- 股数

第一版成交时间取服务端保存时间，不允许页面修改，不提供备注。系统自动补充股票名称、交易日期、手续费、印花税、持仓成本、已实现盈亏以及关联决策。

保存要求：

- 明确显示成功或失败
- 成功后立即刷新持仓和账户
- 使用幂等键防止重复点击产生重复成交
- 买入超过可用现金时允许记录真实成交，但必须产生资金不一致告警
- 暂不提供页面修改；后台必须保留原始记录和可审计的修正能力

### 5.3 当前持仓

策略为单股模式，只展示一张持仓卡：

- 股票名称和代码
- 股数、成本价、现价和市值
- 浮动盈亏和收益率
- 买入日期与时间
- T+0锁定或T+1可卖状态
- 最新模型动作
- VWAP、支撑位和热点退潮状态
- 下一次检查时间

空仓时展示固定Top3、当前观察状态和下一次决策时间。

### 5.4 账户与历史

- 初始资金
- 可用现金
- 当前持仓市值
- 账户总资产
- 已实现和未实现盈亏
- 累计收益率和最大回撤
- 每日、每月收益
- 历史成交和手续费
- 模型建议与实际成交的时间、价格偏差

### 5.5 系统状态与日志

- 后端服务、调度器和交易日状态
- 09:25任务及下一次5分钟任务
- 日线、集合竞价和5分钟行情状态
- LLM模型、提示词版本、请求状态、耗时、Token和费用
- 最近一次成功决策
- 警告和错误
- 手动重跑当前任务
- 完整错误堆栈和一键复制故障上下文

日志按正常、警告、错误分级。首页只显示当前故障，系统状态页提供完整日志。

## 6. 通知

第一版同时支持页面弹框和macOS系统通知，可配置提示音。以下事件触发通知：

- 09:25今日允许或禁止开仓
- 生成新的固定Top3
- 首次出现买入建议
- 首次出现卖出建议
- 硬风控拦截原始建议
- 行情、LLM、调度或数据发生故障

普通等待、继续持有和相同建议不重复通知。每个通知具有唯一事件ID，并保留未读状态，防止定时任务重复弹框。

## 7. 资金与收益

初始资金不在页面设置，通过服务配置提供，默认值为人民币5万元：

```env
INITIAL_CAPITAL=50000
```

首次启动为空仓，初始可用现金等于初始资金。后续账户状态完全由人工成交回填演进：

```text
买入后现金 = 原现金 - 成交价 * 股数 - 买入手续费
卖出后现金 = 原现金 + 成交价 * 股数 - 卖出手续费 - 印花税
总资产 = 现金 + 持仓市值
累计收益率 = 总资产 / 初始资金 - 1
```

第一笔成交产生后不得直接修改初始资金，否则历史收益会被重写。需要修正时应清空测试账本重新初始化，或通过后续设计的资金调整流水处理。

## 8. 故障安全

默认保守处理：

- 09:25核心行情失败：当天禁止开仓。
- LLM失败或返回格式错误：不产生新交易建议。
- 候选股票5分钟行情缺失：不交易该股票。
- 持仓卖出判断失败：保留持仓状态并高优先级通知人工检查。
- 人工回填失败：不改变账户状态并持续告警。
- 服务重启：从持久化数据库恢复状态，不重复执行已处理信号。
- 数据截止时间晚于决策时间或检测到未来数据：拒绝决策并记录严重错误。

系统进入故障状态时显示“安全模式：禁止开新仓”及明确原因。

## 9. 审计与版本

每次决策必须保存：

- 策略版本和参数快照
- LLM供应商、模型和提示词版本
- 输入数据截止时间
- 固定Top3和候选生成依据
- 发送给LLM的结构化输入
- LLM原始输出和解析结果
- 硬规则判定
- 最终展示建议
- 关联人工成交

模型、提示词、参数或数据口径不得静默变化。任何变化需要新策略版本，并与历史冻结版本分别记录。

## 10. 第一版验收标准

- 09:25任务可在交易日自动生成开仓权限和固定Top3。
- 有效状态下每5分钟自动运行，其他状态不浪费LLM调用。
- 新买卖建议能够快速触发页面和macOS通知，且不重复发送。
- 四字段成交回填能够正确改变持仓、现金和收益。
- T+1、单股、不加仓、同日回购冷却均由代码强制执行。
- 服务重启后账户、持仓、候选和待处理建议均可恢复。
- 行情或LLM故障不会产生新的买入建议。
- 每项决策和成交都能通过日志完整追溯。
